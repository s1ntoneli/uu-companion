# Developer ID signing and notarization (macOS)

Source builds use ad-hoc signing, appropriate only for development. They are not automatically safe for redistribution. For a production release, use an Apple Developer ID Application certificate and Apple notarization. Never disable Gatekeeper or macOS SIP.

If you own a Developer ID Application signing identity:

    UU_DRIVER_SIGN_IDENTITY="Developer ID Application: YOUR ORGANIZATION (TEAMID)" ./NativeMic/package.sh
    UU_COMPANION_SIGN_IDENTITY="Developer ID Application: YOUR ORGANIZATION (TEAMID)" ./build.sh

The helper uu-sender and top-level application are signed with the hardened runtime + audio-input entitlement. Other helpers use hardened runtime as well. Built-in Native Mic driver needs a separate, stable Developer ID signature. The local pkg generated by NativeMic/package.sh is NOT yet Developer ID Installer signed.

Then check each signature independently:

    codesign --verify --deep --strict --verbose=2 build/uu伴侣.app
    codesign -dv --verbose=2 build/uu伴侣.app
    codesign -d --entitlements :- build/uu伴侣.app/Contents/MacOS/uu-sender

For notarization, the full distribution must be signed appropriately, including the driver installer and every executable. A Developer ID Installer certificate may be needed to sign the flat pkg:

    productsign --sign "Developer ID Installer: YOUR ORGANIZATION (TEAMID)" unsigned.pkg signed.pkg

Submit the final archive or installer to Apple's notary service with an authorized notarytool keychain profile, wait for Accepted, staple, and verify using spctl and stapler validate before a public binary release. Apple credentials stay in the local Keychain. Never store app-specific passwords, App Store Connect private keys, credentials or signing identities with private keys in Git.

This repository DOES NOT claim the preview is Apple notarized until the actual submission succeeds. Run a separate first-install/permissions test on a clean Mac before a production release.

## Public notarized ZIP without an Installer certificate

Developer ID Installer is distinct from Developer ID Application. Apple rejects an unsigned .pkg nested inside App Resources, reporting “The binary is not signed”. The public alternative is an Apple-notarized ZIP with two independently Developer-ID-signed components: uu伴侣.app built with UU_DISTRIBUTION_MODE=1, and UUMicNative.driver built with UU_DRIVER_SIGN_IDENTITY, plus INSTALL-MAC.md and Finder shortcuts to /Applications and /Library/Audio/Plug-Ins/HAL.

Users copy the driver through Finder with normal administrator authorization, then restart macOS. Never disable Gatekeeper or SIP. A future one-click flat installer must be signed by a distinct Developer ID Installer certificate and notarized.


Apple notarization returned Accepted for Preview 3 with the App and separate signed driver without an unsigned .pkg. Gatekeeper on a second Mac accepted the App as Notarized Developer ID. ZIP files cannot be stapled; stapler also could not write its ticket under this remote execution sandbox. First run therefore requires online notarization verification. See INSTALL-MAC.md.

### Reproducible signed ZIP

The source repository includes scripts/package-notarized-zip.sh to build the signed App and signed Native Mic driver into one archive (no unsigned nested pkg), and scripts/notarize-zip.sh to submit the exact archive and require an Accepted status. These scripts read signing identity names and Apple API credential paths from the operator environment; they never commit or print private keys. For notarization, provide NOTARYTOOL_PROFILE or ASC_KEY_PATH, ASC_KEY_ID, ASC_ISSUER_ID. The public ZIP contains both Finder shortcuts, a setup guide, and native binaries.


## Single-App distribution with embedded signed audio plugin

The distribution build embeds a separately Developer-ID-signed Native Mic driver in the resources directory of uu伴侣.app, without nesting an unsigned pkg. On the receiving Mac the user clicks a single Install action. The app calls the normal macOS administrator authentication via AppleScript and osascript. The driver is copied to a staging area outside HAL, verified using codesign --strict, assigned root ownership, then moved into /Library/Audio/Plug-Ins/HAL/UUMicNative.driver. The previous version is backed up outside HAL. Restart the receiving Mac after installation to allow Core Audio to load the audio plugin.

A notarization Accepted response alone is not proof that installation succeeds. The admin prompt, plugin presence, and real sound capture must be validated separately on a Mac. Never bypass Gatekeeper or SIP.
